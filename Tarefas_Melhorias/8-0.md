Você está trabalhando no projeto **curti Z**.

Quero implementar a infraestrutura completa de comunicação por e-mail utilizando **Resend**, preparada para produção.

O objetivo é transformar e-mail em um módulo real do sistema, cobrindo:

* autenticação;
* segurança da conta;
* compras;
* pedidos;
* pagamentos;
* entregas;
* cancelamentos;
* reembolsos;
* trocas e devoluções;
* atendimento;
* representantes;
* notificações administrativas;
* campanhas;
* novos produtos;
* comunicações personalizadas;
* respostas por e-mail.

Faça as alterações diretamente no código.

Não implemente apenas um `/api/send-email`.

Quero uma arquitetura centralizada, auditável, segura e extensível.

---

# 1. REGRA PRINCIPAL

Crie um único domínio lógico de e-mail compartilhado pelo projeto.

Não espalhe:

```text
resend.emails.send(...)
```

aleatoriamente por dezenas de componentes e rotas.

Crie uma camada centralizada de e-mail no servidor, reutilizável por Store e Panel.

Conceitualmente:

```text
evento do sistema
       ↓
serviço de notificações
       ↓
template
       ↓
preferências/permissões
       ↓
Resend
       ↓
webhooks
       ↓
status/auditoria
```

Adapte aos packages e arquitetura atuais do monorepo.

---

# 2. PROVIDER

O projeto atualmente possui suporte configurável para provider de e-mail.

Preserve essa arquitetura.

Quando:

```text
EMAIL_PROVIDER=resend
EMAIL_ENABLED=true
```

utilizar Resend.

Quando estiver desabilitado:

não tentar enviar.

Não gerar falso positivo de envio.

# 4. CHAVES SEPARADAS

Estruture o sistema para permitir separação por privilégio.

## Transacional

`RESEND_API_KEY`

Usada somente para envio normal.

## Marketing

`RESEND_MARKETING_API_KEY`

Usada somente no backend autorizado responsável por:

* Contacts;
* Topics;
* Broadcasts;
* campanhas.

## Receiving

`RESEND_INBOUND_API_KEY`

Usada somente pelo backend que precisa recuperar conteúdo de e-mails recebidos.

Nunca enviar qualquer uma dessas chaves para o navegador.

Exemplos:

* pedido;
* segurança;
* reembolso;
* atendimento.

## Marketing

Exemplos:

* promoções;

* newsletters.

Marketing deve respeitar:

* opt-in;
* Topics;

* suppression.
