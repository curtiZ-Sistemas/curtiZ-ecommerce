# 1. AUTORIZAÇÃO SERVER-SIDE

Confirme que nenhuma função sensível depende somente da interface.

Teste conceitualmente e corrija quando necessário:

* cliente tentando acessar painel interno;
* representante tentando acessar administrativo;
* operacional tentando executar ação administrativa;
* gerencial tentando executar ação exclusiva de administrador;
* usuário alterando IDs diretamente na URL;
* usuário modificando payload para acessar entidade de outro usuário.

A UI pode esconder ações, mas o servidor precisa bloquear também.

---

# 2. IDOR / BOLA

Audite endpoints que recebem IDs como:

* usuário;
* pedido;
* endereço;
* produto;
* representante;
* cliente;
* chamado;
* cupom;
* estoque.

Nunca permita acesso somente porque o cliente informou um ID válido.

Valide:

* proprietário;
* role;
* permissão;
* escopo.

---

# 3. SUPABASE RLS

Revise políticas relevantes.

Não desligue RLS para fazer algo funcionar.

Garanta que:

* cliente veja somente seus dados privados;
* representante veja somente dados permitidos;
* operacional tenha escopo operacional;
* gerente tenha escopo gerencial;
* administrador tenha acesso conforme regras existentes.

Evite policies excessivamente abertas.

---

# 4. SERVICE ROLE

Confirme que:

`SUPABASE_SERVICE_ROLE_KEY`

ou qualquer secret privilegiado:

* nunca entra no browser;
* nunca usa `NEXT_PUBLIC_*`;
* nunca aparece em HTML;
* nunca aparece em bundle client;
* nunca aparece em logs;
* nunca aparece em mensagens de erro.

---

# 5. SECRETS

Procure por possíveis:

* tokens;
* chaves;
* credenciais;

* secrets hardcoded.

Verifique principalmente:

* código;
* configs;

* scripts;
* documentação;
* exemplos.

Não imprimir secrets encontrados no relatório.

Se encontrar secret real versionado:

Não reproduza seu valor.

# 9. HEADERS

Revise headers de segurança existentes.
