Você está trabalhando no projeto **curti Z**.

Esta tarefa é uma etapa de **Direção Visual, UI, UX, responsividade e microinterações**.

O projeto já está passando por melhorias estruturais nos painéis e Design System.

NÃO desfaça essas melhorias.

NÃO reconstrua o sistema.

NÃO substitua a identidade atual.

Quero refinar profundamente a experiência visual do curti Z para que deixe de parecer apenas um site tecnicamente bem feito e passe a ser também:

* interessante;
* agradável;
* moderno;
* comercial;
* envolvente;
* elegante;
* memorável;
* confortável de usar;
* visualmente vivo.

O resultado NÃO deve parecer um template genérico ou interface criada por IA.

---

# 1. CONCEITO PRINCIPAL

A nova direção visual do curti Z deve seguir o conceito:

**Editorial. Limpo. Tátil. Dinâmico. Humano. Comercial.**

Outra regra importante:

> Minimalista quando precisa ser funcional. Expressivo quando precisa vender.

Isso significa:

## Loja pública

Pode ser:

* mais emocional;
* fotográfica;
* dinâmica;
* editorial;
* inspiradora;
* comercial.

## Área do Cliente e painéis

Devem continuar:

* claros;
* compactos;
* organizados;
* profissionais;
* rápidos;
* confortáveis para uso diário.

Mas não podem ficar monótonos ou cansativos.

---

Inspire-se em princípios usados por grandes marcas, lojas e e-commerces profissionais, especialmente nos setores de:

* moda;

* grandes marketplaces: clareza funcional e organização;
* grandes sistemas SaaS: UX consistente e feedback imediato.

NÃO copie visualmente nenhuma marca.

Absorva apenas princípios de:

* hierarquia;
* ritmo;
* proporção;
* fotografia;
* movimento;
* navegação;
* organização.

O resultado precisa continuar sendo **curti Z**.

# 3. NÃO ALTERAR A LOGO

REGRA CRÍTICA.

A logo atual NÃO deve ser redesenhada.

NÃO:

* trocar a logo;
* alterar suas cores;
* adicionar fundo atrás dela;
* adicionar caixa;
* adicionar círculo;
* adicionar gradiente;
* adicionar glow;
* adicionar sombra artificial para destacá-la;
* modificar o arquivo visual para resolver problemas de contraste.

A solução para a logo deve acontecer através do **layout ao redor dela**.

---

# 4. DAR MAIS PRESENÇA À LOGO

Atualmente a logo pode parecer pequena, apagada ou escondida no header.

Resolva isso usando:

* tamanho;
* posicionamento;
* respiro;
* alinhamento;
* proporção;
* redução da competição visual ao redor.

No desktop:

* aumentar moderadamente a presença visual da logo;
* preservar proporção;
* criar uma zona de respiro ao redor;
* evitar que busca e outros elementos fiquem colados;
* garantir alinhamento vertical perfeito;
* dar à marca importância equivalente ao restante do header.

Use algo aproximadamente na faixa visual de 105–120 px de largura apenas como referência inicial.

Adapte ao SVG real e ao layout.

Não force tamanho fixo inadequado.

---

# 5. FUNDO PRINCIPAL

A direção atual usando:

`#eeeeee`

deve ser preservada e refinada.

Considere:

```css
--page-background: #eeeeee;
--surface-primary: #ffffff;
--surface-soft: #f7f7f5;
--text-primary: #161616;
--text-secondary: #686868;
```

Preserve a cor oficial da marca existente.

Não invente uma nova cor principal.

---

# 6. COMO USAR O #EEEEEE

Não transforme tudo em cinza.

Use `#eeeeee` como:

* fundo estrutural;
* separação de seções;
* fundo de painéis;
* área ao redor de superfícies;
* meio de criar profundidade sem sombras.

Use branco para:

* cards;
* formulários;
* áreas principais;
* tabelas;
* superfícies de conteúdo.

Use superfícies suaves apenas quando necessário.

---

* glassmorphism;
* neon;
* glow;
* gradientes coloridos genéricos;
* sombras enormes;
* blur decorativo;
* cards gigantes excessivamente arredondados;

* animações chamativas;

---

# 8. PROFUNDIDADE SEM SOMBRA

Priorize:

`background → surface → border → spacing → content`

em vez de:

`card → border-radius gigante → shadow`

Exemplo conceitual:

```css
background: #fff;
border: 1px solid #dedede;
border-radius: 6px;
```

Use sombras apenas quando forem funcionalmente necessárias, como:

* dropdown;
* menu flutuante;
* modal;
* drawer;
* popover.

Mesmo nesses casos, mantenha-as discretas.

# 10. BUSCA NO DESKTOP

Hoje a busca tem presença visual muito grande.

Refine.

Ela precisa continuar:

* fácil de encontrar;
* larga;
* funcional.

Mas não deve parecer mais importante do que:

* marca;
* campanha;
* produto.

Integre melhor:

* campo;
* ícone;
* ação de busca.

Evite botão de busca excessivamente dominante dentro do header.

Se a UX atual permitir, o próprio campo pode executar via:

* Enter;
* ícone;
* botão visualmente integrado.

Preserve acessibilidade.

# 11. NAVEGAÇÃO DESKTOP

* mudança sutil de opacidade;

Mantenha boa área clicável.

* retorna de forma suave.

Se esconder parcialmente o header for implementado, faça somente se a UX permanecer previsível.

Não prejudique:

* busca;
* navegação;
* acessibilidade;
* mobile.

Evite comportamento nervoso ou piscando.

# 30. ESCALA DE MOVIMENTO

Padronize aproximadamente:

## Interação rápida

140–180 ms

Para:

* botões;
* ícones;
* coração;
* checkbox;
* badges.

## Interação normal

220–300 ms

Para:

* dropdown;
* menu;
* drawer;
* modal.

## Movimento editorial

400–550 ms

Para:

* hero;
* entrada de campanha;
* entrada de seção.

Use easing consistente.

Pode usar como referência:

```css
cubic-bezier(.22, 1, .36, 1)
```

Não aplicar cegamente.

---

# 31. PREFERS-REDUCED-MOTION

Obrigatório.

Respeite:

```css
@media (prefers-reduced-motion: reduce)
```

Desative ou simplifique animações quando solicitado pelo sistema operacional.

---

# 32. ENTRADA DAS SEÇÕES

Pode utilizar:

```text

```

* uma vez;

* sem exagero.

# 33. BOTÕES

Melhore sensação tátil.

No hover:

* mudança discreta;
* seta pode deslocar 3–4 px;
* fundo pode mudar de forma sutil;
* texto continua legível.

No click:

* feedback imediato.

Nada de glow.

---

# 34. FAVORITOS

Ao clicar:

* atualizar imediatamente;
* pequena resposta visual de escala;
* estado final claro.

Não usar:

* confete;
* partículas;
* animações exageradas.

---

# 35. ADICIONAR À SACOLA

Melhore o feedback.

Fluxo ideal:

1. clique;
2. loading curto;
3. confirmação;
4. contador da sacola atualizado;
5. feedback visual claro.

Se a arquitetura atual suportar sem refatoração excessiva, pode usar mini drawer lateral mostrando:

* imagem;
* nome;
* variante;
* quantidade;
* preço;
* ver sacola;
* finalizar compra.

Não reimplementar carrinho apenas para criar esse efeito.

---
