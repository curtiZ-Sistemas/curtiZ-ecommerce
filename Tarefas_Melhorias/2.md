Você está trabalhando no sistema **curti Z**.

Quero uma melhoria profunda de **layout, interface, UI e UX** dos seguintes painéis:

* Administrativo
* Gerencial
* Operacional

O objetivo é fazer os três painéis parecerem um **sistema profissional de gestão**, extremamente organizado, intuitivo, rápido, responsivo e sem confusão para o usuário.

Não quero apenas mudanças de cores.

Quero uma revisão real da experiência de uso.

---

# OBJETIVO PRINCIPAL

Transforme os painéis existentes em interfaces:

* modernas;
* profissionais;
* rápidas;
* responsivas;
* intuitivas;
* consistentes;
* visualmente limpas;
* fáceis de aprender;
* fáceis de navegar;
* adequadas para uso diário;
* com informações importantes claramente priorizadas.

O usuário deve entender rapidamente:

1. onde está;
2. o que está acontecendo;
3. quais ações pode realizar;
4. o que precisa de atenção;
5. como voltar ou navegar para outra área.

# 9. DASHBOARDS

Revise os dashboards.

Cada role deve possuir informações relevantes para sua função.

* valor;
* contexto;
* significado;
* estado quando necessário.

Pedidos pendentes
12

12 pedidos.

# 11. MOBILE

Os painéis devem funcionar muito bem em:

* desktop;
* notebook;
* tablet;
* celular.

Não basta diminuir tudo.

No mobile:

* sidebar deve virar drawer/menu;
* tabelas precisam continuar utilizáveis;
* botões precisam ser clicáveis;
* formulários não podem ultrapassar a tela;
* modais precisam caber no viewport;
* ações importantes não podem desaparecer;
* conteúdo não pode gerar scroll horizontal desnecessário.

---

---

# 13. FEEDBACK DAS AÇÕES

Toda ação importante deve possuir feedback.

Exemplo:

Usuário clica em salvar.

Mostrar imediatamente:

* loading;
* sucesso;
  ou
* erro compreensível.

Evite botões que parecem não fazer nada.

Implemente estados de:

* loading;
* success;
* error;
* disabled.

Evite clique duplo criando ações duplicadas.

---

# 14. LOADING

Use o padrão de loading profissional do sistema.

Para carregamento de página:

* spinner central quando apropriado;
* skeleton em conteúdos estruturados quando oferecer UX melhor.

Para pequenas operações:

* loading local.

Exemplo:

Salvar produto

deve mostrar estado dentro do próprio botão, não necessariamente bloquear a tela inteira.

---

# 15. EMPTY STATES

Nunca deixar uma área simplesmente vazia.

Exemplo:

Nenhum pedido encontrado.

Adicionar orientação útil:

"Não existem pedidos com esse filtro."

Quando apropriado, oferecer ação:

"Limpar filtros"

ou

"Cadastrar produto".

---

# 16. ERROS

Melhore mensagens de erro.

Evite mostrar:

* stack trace;
* erros técnicos do Supabase;
* códigos incompreensíveis.

Usuário deve receber mensagens como:

"Não foi possível carregar os pedidos. Tente novamente."

Logs técnicos podem continuar no servidor quando apropriado.

---

# 17. CONFIRMAÇÕES

Ações destrutivas devem exigir confirmação.

Exemplos:

* excluir;
* cancelar;
* remover;
* desativar.

Modal deve informar claramente o que acontecerá.

Evite `window.confirm()` se já existir sistema de modal reutilizável.

---

# 18. ACESSIBILIDADE

Garanta:

* navegação por teclado;
* foco visível;
* labels;
* `aria-*` quando necessário;
* contraste;
* botões sem depender apenas de ícones;
* targets adequados para touch.

Icons de ação devem ter `aria-label` ou texto acessível.

---

# 19. PERFORMANCE DA UI

Não prejudique performance em nome de estética.

Evite:

* animações pesadas;
* bibliotecas enormes;
* gráficos desnecessários;
* componentes client onde Server Component bastaria;
* renders desnecessários;
* chamadas duplicadas.

Lazy-load conteúdo pesado quando fizer sentido.

---

# 20. NAVEGAÇÃO

A navegação deve ser previsível.

Use breadcrumbs em páginas profundas.

Exemplo:

Produtos
→ Produto
→ Editar

O usuário nunca deve se sentir perdido.

---

# 21. FILTROS

Filtros devem ser organizados e claros.

Evite dezenas de selects sempre visíveis.

Se houver muitos filtros:

* mostrar principais;
* permitir abrir filtros avançados.

Mostrar claramente filtros ativos.

Adicionar opção de limpar filtros.

---

# 22. BUSCA

Onde existir grande quantidade de dados, garantir busca fácil.

Busca deve ter:

* placeholder claro;
* debounce quando consulta backend;
* loading;
* estado vazio;
* tratamento de erro.

Evite enviar request a cada tecla sem necessidade.

---

# 23. STATUS

Exemplos:

* ativo;
* inativo;
* pendente;
* aprovado;
* enviado;
* entregue;
* cancelado.

Use badges consistentes.

Nunca depender somente da cor.

Inclua texto.

Exemplo:

Produtos

Título:
Produtos

Ação principal:
