# 1. CPF

Todos os campos de CPF da Store devem aceitar no máximo:

**11 dígitos numéricos reais.**

O usuário não deve conseguir inserir mais do que isso.

Enquanto digita, formate automaticamente:

```text
12345678901
```

para:

```text
123.456.789-01
```

A máscara deve acompanhar a digitação progressivamente.

Exemplo:

```text
1
12
123
123.4
123.456.7
123.456.789-01
```

A implementação deve:

* ignorar letras;
* impedir quantidade acima de 11 dígitos;
* permitir backspace normalmente;
* funcionar com colar/copiar;
* sanitizar texto colado;
* funcionar no mobile;
* usar teclado numérico quando apropriado.

Use internamente somente os dígitos quando enviar CPF ao servidor, salvo se a arquitetura atual exigir outro formato.

Além do limite visual, mantenha validação server-side.

Se já existir função compartilhada de CPF, reutilize-a.

Não duplicar lógica em vários componentes.

---

# 2. VALIDAÇÃO REAL DE CPF

Se já houver validação dos dígitos verificadores, preserve e centralize.

Se não houver, implemente uma validação adequada.

Não considerar válido simplesmente porque possui 11 números.

Não aceitar sequências obviamente inválidas como:

```text
00000000000
11111111111
22222222222
```

A validação do frontend é UX.

A validação definitiva deve existir também no servidor quando esse dado for processado.

---

# 3. TELEFONE

Para telefone brasileiro, quero que o usuário digite somente os números, incluindo o **DDD**.

Limite máximo:

**11 dígitos numéricos.**

Exemplo celular:

```text
31999999999
```

deve ser apresentado automaticamente como:

```text
(31) 99999-9999
```

Se houver suporte para telefone com 10 dígitos:

```text
3133334444
```

mostrar:

```text
(31) 3333-4444
```

A máscara deve acontecer progressivamente enquanto a pessoa digita.

Não exigir que o usuário digite manualmente:

* parênteses;
* espaços;
* hífen.

O campo deve:

* bloquear letras;
* limitar a 11 dígitos;
* sanitizar paste;
* funcionar corretamente com backspace;
* funcionar em celular;
* usar `inputMode="numeric"` ou equivalente apropriado.

No backend, normalize para somente dígitos quando apropriado.

---

# 4. E-MAIL

Todos os campos principais de e-mail relacionados ao fluxo de cliente/checkout devem possuir:

```text
máximo de 120 caracteres
```

Não mostrar texto ao usuário dizendo:

"Máximo de 120 caracteres".

Simplesmente impedir que continue digitando além do limite.

Use:

```text
maxLength=120
```

ou solução equivalente apropriada.

Preserve:

* `type="email"`;
* autocomplete apropriado;
* validação de formato;
* validação server-side.

Não truncar silenciosamente um e-mail recebido diretamente por API.

O servidor deve rejeitar payload inválido.
